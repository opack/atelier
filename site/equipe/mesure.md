# Mesurer

Peu d’indicateurs, relevés à la main au début. L’objectif n’est pas un tableau de bord, mais de savoir si la méthode aide.

## Les indicateurs utiles

- **Délai** de la signature à la PR fusionnée, par type de chantier.
- **Temps de revue** par PR, et nombre d’allers-retours.
- **Défauts** découverts après livraison, rattachés au chantier d’origine.
- **Rejets aux portes** : à quelle étape le travail généré échoue le plus souvent (spec incomplète, tests, revue).
- **Où l’IA a ralenti** : code inconnu dans une zone critique, bug subtil coûteux, spec floue. À noter dans le bilan.

## Ce qu’il ne faut pas mesurer

Le nombre de lignes générées, le nombre de prompts, le nombre de tests. Ils mesurent l’activité, pas la valeur.

## Être honnête

Seul sur un projet personnel, vous n’avez pas d’échantillon : parlez de ressenti, pas de chiffres, sauf si vous en avez relevé. Et dites où l’IA vous a ralenti : c’est un signe de maturité, pas de faiblesse.
